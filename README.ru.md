## Быстрый старт

```bash
curl -fsSL https://krllx.github.io/longrun/install.sh | bash
```

> [!NOTE]
> Установщик добавляет скилл с командой `longrun` для терминала, хуки в `~/.claude/settings.json` и фоновый таймер, который срабатывает раз в пять минут. Спросит про установку уведомлений. `install.sh --uninstall` убирает все, что добавил.

<details>
<summary>Что именно происходит на машине</summary>

- `~/.claude/settings.json` - 11 хуков и два правила в permissions, которые разрешают агенту вызывать `longrun`. Файл сначала копируется в `~/.claude/backups/`, хуки, добавленные не longrun, не трогаются.
- `~/.claude/skills/longrun/` и симлинк `~/.local/bin/longrun`.
- MCP-сервер `longrun` в user scope (`claude mcp add`) - он дает агенту инструменты `ask` и `notify`.
- **фоновый таймер** раз в пять минут: агент launchd на macOS, systemd user timer или строка в cron на Linux. Он проверяет заведенные watch и состояние сессий. Это несколько shell-проверок без модели и без токенов; сессию он будит, только когда ваше условие выполнилось. Флаг `--no-timer` отключает таймер.
- **уведомления на рабочем столе**, если ответить да на вопрос установщика: на macOS `brew install terminal-notifier`, если его нет, небольшое приложение-отправитель уведомлений в `~/.claude/longrun/notifier/` и одно тестовое уведомление, чтобы macOS запросила разрешение. На Linux только проверяется наличие `notify-send`. Флаги `--notify` и `--no-notify` задают ответ заранее.

Нужны macOS или Linux, Claude Code и python3 3.9+. Из клонированного репозитория запускается тот же [`install.sh`](install.sh).

</details>

Далее нужно открыть проект в Claude Code (новый или уже существующий) и сказать **"настрой longrun"**. Или из терминала:

```bash
cd ~/my-project && longrun init && claude "настрой longrun"
```

После этого команды не нужны, достаточно сказать: *"запиши"*, *"что мы уже пробовали"*, *"скажи, когда PR вольется"*.

> **Устройство скилла и примеры:** [курс](https://krllx.github.io/longrun/course/ru/) - одиннадцать коротких частей, около 15 минут.

<details>
<summary><b>Уведомления на рабочем столе</b> - зачем они и что спрашивает установщик</summary>

- **Зачем нужны:** сессия и так узнает о halt, сработавшем watch и законченном ходе; баннер нужен, чтобы *вы* заметили это, пока смотрите в другое окно. Для работы скилла они не нужны.
- **macOS:** `terminal-notifier` через Homebrew (встроенного способа показать баннер у macOS нет) и один запрос разрешения. Если при установке ответили нет, позже уведомления включаются командой `longrun notify setup`.
- **Linux:** `notify-send` (`libnotify`), в большинстве окружений рабочего стола он уже есть.

`longrun notify --test` проверяет, что уведомление действительно доходит до экрана. Две настройки, на которые стоит взглянуть: `notify_turn_end unfocused` (баннер, когда сессия закончила ход, а окно Claude не в фокусе) и `longrun important on|next` для той сессии, которую нельзя пропустить. Инструмент `notify`, которым пользуется агент, предоставляет MCP-сервер `longrun`; его регистрирует установщик. Подробности и особенности macOS: [docs/REFERENCE.ru.md](docs/REFERENCE.ru.md).

</details>

## Коротко

**Работает само, с первой сессии:** агент ведет заметки на диске - тупики, решения, факты, - а хуки возвращают их после каждой компакции, `/clear` и resume; хуки указывают суммаризатору компакции, что сохранить; на каждом ходу видно, что изменили другие сессии проекта.

**По просьбе или когда агент сам видит необходимость:** "скажи, когда PR вольется" (watch, который не тратит токены на ожидание), сообщения и задачи между сессиями, уведомление, когда нужная вам сессия закончила ход, и одна сессия, ведущая остальные к заданной цели.

## Зачем

| Без longrun | С longrun |
|---|---|
| Компакция сжимает историю в резюме, и первыми пропадают причины решений: почему подход отбросили, почему выбрали этот путь. Через полчаса агент предлагает правку, которую сам уже откатил. | **Заметки на диске.** По строке на тупик, решение и факт. Общие видят все сессии, свои возвращаются после каждой компакции, `/clear` и resume. |
| Вторая сессия не знает о первой. Одна открыла PR, другая говорит "PR еще не создан". | **Сообщения и задачи.** Сессия шлет сообщение или раздает задачу, и это приходит другой сессии как ход пользователя. |
| "Скажи, когда PR вольется" превращается либо в цикл опроса, который тратит токены, либо в паузу на заданное время (sleep), после которой событие уже давно произошло или еще не наступило. | **Watch.** Фоновый таймер проверяет условие раз в пять минут без модели и будит сессию, когда оно выполнилось. Надежно, реактивно, бесплатно. |
| Пять сессий на одном проекте, и только человек знает, что сделано, что застряло и что дальше. | **Оркестратор.** Одна сессия ведет борд, раздает задачи, замечает застрявшие сессии и спрашивает человека через диалоговое окно, только когда без него не обойтись. |

Один python-файл, без зависимостей.

## Четыре способа координации

> [!NOTE]
> Команды ниже - это то, что агенты выполняют сами: скилл говорит им, когда записать заметку, когда отправить сообщение, когда завести watch. Заучивать тут нечего: вы говорите *"запиши"* или *"скажи, когда PR вольется"*, а чаще не говорите ничего. Они приведены потому, что любую из них при желании можно выполнить руками.

### 1. Общие документы на диске

Один `.longrun/` на проект хранит заметки, которые видят все сессии. У каждой сессии есть и свои заметки, вне дерева репозитория. Хуки возвращают и те и другие после каждой компакции, `/clear` и resume, а на каждом ходу показывают, что изменили другие сессии.

```bash
longrun add --shared -t pin "PR 42 = branch feature/checkout"     # для всех сессий
longrun add -t dead "retry on 429 does not help, limit is per org"  # для этой
longrun recall 429                                                  # поиск по всему
```

### 2. Делегирование той сессии, у которой есть контекст

Сообщение другой сессии приходит как ход пользователя. Работающая сессия получает его сразу через свой сокет. Остановленная заберет его из inbox проекта на следующем ходу; разбудить ее сразу можно флагом `--resume`, но это запуск `claude -p` в фоне, а значит, токены. Сессия адресуется по имени, которое вы видите в сайдбаре.

```bash
longrun send "PR 43: платежи" "PR 42 влит, перебазируйся на main"
longrun board assign T8 "PR 43: платежи"      # задача вместо сообщения
```

### 3. По событию: ждать, не тратя токены

Watch - это детерминированная проверка, которую таймер запускает раз в пять минут без участия модели (launchd на macOS, systemd-таймер пользователя или cron на Linux). Когда условие выполнилось, сессия получает текст из `--then` сообщением. Если ноутбук спит, проверка просто откладывается.

```bash
longrun watch add --to "PR 43: платежи" --then "перебазируйся на main" -- pr-merged 42
longrun watch add --then "проверь выкатку" -- at 10:00
```

Проверки: `pr-merged` (GitHub через `gh`), `pr-status`, `at`, `file`, `http`, `cmd`.

### 4. Самостоятельность, которую включаете вы: одна сессия ведет остальные

Одна сессия берет роль оркестратора и ведет борд: цель, задачи, факты извне. Рабочие сессии берут, закрывают и помечают задачи как заблокированные. Каждое изменение на борде будит оркестратора: он раздает следующую задачу, разбирает блокировки или спрашивает человека диалогом поверх всех окон. Он не опрашивает сессии и сам их не запускает: в приложении он оставляет чип, который открывает сессию по клику, а в терминале выдает первую строку, которую нужно вставить в новую сессию.

```bash
longrun orchestrate start --goal "довести корзину до релиза"   # в ведущей сессии
longrun board take T7; longrun board done T7 "PR 42 влит"      # в рабочей
longrun ask "Мержим PR 42?" --options "Да,Нет"                 # диалог, ответ приходит сразу
```

Управление остается у человека: убить зависший процесс (`longrun interrupt`), остановить все сессии (`longrun halt`), снять остановку. Фоновый наблюдатель и оркестратор только предлагают. Необязательно и по умолчанию выключено: бюджет на 5-часовое окно (`longrun budget on`). Он останавливает все сессии, когда лимит расходуется быстрее плана, и спрашивает, что делать.

## Как это работает

```mermaid
sequenceDiagram
    participant S as сессия Claude Code
    participant L as longrun (хуки)
    participant D as заметки на диске
    S->>L: сессия стартует
    L->>D: прочитать общие заметки проекта и свои заметки этой сессии
    L-->>S: дайджест: что известно, кто еще работает, что ждет
    Note over S: агент работает, пишет по строке на тупик или решение
    S->>D: longrun add ...
    S->>L: каждый ход
    L-->>S: что изменили другие сессии, сообщения для вас
    S->>L: скоро компакция
    L->>D: снимок и указание суммаризатору, что сохранить
    S->>L: сессия стартует снова (после компакции, /clear, resume)
    L-->>S: тот же дайджест плюс место, где остановились
```

**Старт.** Хук находит проект по каталогу и печатает дайджест: общие заметки, свои заметки, другие сессии (активны ли, чем занимались в последний раз), ожидающие watch, недоставленные сообщения.

**Работа.** Агент пишет по строке на тупик, решение или добытый факт. Хуки считают правки и пишут упавшие команды в журнал. После долгой серии правок без заметки - одно напоминание агенту записать ее.

**Каждый ход.** Доставляются сообщения из inbox. Изменения общих заметок другими сессиями приходят в виде дельты: `+` добавлено, `~` переписано, `-` удалено.

**Компакция.** До нее - снимок последних просьб, правленых файлов и недавних падений, плюс инструкции суммаризатору: сохранить тупики с причинами, сохранить точные строки, выбросить то, что можно снова получить одним чтением файла. Промпт резюме у автокомпакции и у `/compact <текст>` один и тот же, так что это тот же способ управлять резюме, только автоматический: не нужно ловить момент перед компакцией. После компакции резюме дословно сохраняется в архив. Следующий старт печатает дайджест и блок HANDOFF, и сессия продолжает с того же места. Resume и `/clear` продолжают те же заметки, форк получает копию.

**Уборка.** Раз в час: старые записи в архив (кроме `pin`), журналы обрезаются, молчавшие сессии архивируются. Команда `add` отказывает, когда лимит заметок исчерпан, и подсказывает, что можно удалить. Ничего не удаляется молча.

## Три сущности

| Сущность | Что это | Что хранит |
|---|---|---|
| **Проект** | Один каталог `.longrun/`, в папке проекта или вне дерева (`--external`) | Общие заметки, inbox, борд, архив |
| **Сессия** | Один разговор Claude Code; в приложении - строка в сайдбаре. Resume выдает новый id, longrun связывает старый id с новым | Свои заметки, журнал, счетчики, последний статус |
| **Каталог** | Папка, где сессия стартовала: корень репозитория, worktree, подкаталог | Ничего. Только говорит, к какому проекту относится сессия |

Worktree привязывается командой `longrun link <проект>` и своего хранилища заметок не имеет.

## Что писать

Критерий один: **можно ли получить это заново одной командой, чтением файла или grep?** Если да, записывать не нужно.

| Тег | Что | Куда |
|---|---|---|
| `dead` | подход не сработал, и почему | свои; общие, если в тот же тупик может зайти другая сессия |
| `decision` | выбор и причина | общие, если касается других |
| `fact` | факт об окружении, который дорого достался | общие |
| `pin` | факт без срока давности: номер PR, ветка, хост | общие |
| `ctx` | рамки задачи от человека | свои |
| `todo` | короткий список незавершенного | свои |

Вехи (запушил, PR открыт, тесты зеленые) - в журнал: `longrun log "PR opened"`. То, что переживет задачу (кто пользователь, как он работает), - в автопамять Claude Code, а не в longrun.

## Команды

```bash
longrun init [--external] | link <проект> | where | onboard | config
longrun add [--shared] -t TAG "..." | rm | replace | notes | prune | log "..." | recall <слово>
longrun status | send [--list] [--resume] КТО "..."
longrun watch add --to КТО --then "..." -- pr-merged 42 | at 10:00 | cmd '...' | file /путь | http URL
longrun orchestrate start --goal "..." | board | fact | ask | halt | resume | interrupt | budget
```

Все флаги, форматы файлов и проверенные факты о Claude Code: [docs/REFERENCE.ru.md](docs/REFERENCE.ru.md). Устройство оркестратора и что осталось: [docs/ORCHESTRATOR.ru.md](docs/ORCHESTRATOR.ru.md).

<details>
<summary><b>Частые вопросы</b></summary>

**Агент говорит "PR еще не создан", хотя он есть.** Этого факта нет в общих заметках, добавьте его: `longrun add --shared -t pin "PR 42 = branch feature/checkout"`.

**Сессия в worktree не видит заметок проекта.** `longrun where` должен показать проект. Если пишет "not initialised": `longrun link <проект>` из этого worktree.

**Сообщение отправлено, а сессия молчит.** `longrun send --list`: если адресат в статусе stopped, сообщение лежит в inbox и придет на следующем ходу. Нужно доставить сейчас - добавьте `--resume`.

**Watch не срабатывает.** `longrun watch status`, `longrun watch ls --all`, `longrun watch test -- <та же проверка>`. Частая причина - относительный путь или alias в `cmd`.
</details>

## Разработка

```bash
bash tests/run.sh            # 202 регрессионные проверки, без API
bash tests/scenarios.sh      # 30 сценариев, по одному на задачу
bash tests/orchestrator.sh   # 67: слой оркестратора
bash tests/ask.sh            # 30: диалог и MCP-сервер
```

Установщик копирует файлы в `~/.claude/skills/longrun/`; правки в репозитории сами по себе не применяются. Уже запущенная сессия подхватывает обновление без перезапуска, потому что хук - отдельный процесс на каждое событие.
