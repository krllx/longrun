# План переработки longrun под манифест

Составлен 2026-09-16 по разбору кода на коммите `24af04b` (ветка `pages-install-url`,
версия 0.5.1). Номера строк ниже относятся к этому коммиту и поплывут после первого
же этапа: ориентируйся по именам функций, строки только подсказка.

## Зачем этот план

Скилл решил боли из второй половины `MANIFESTO.ru.md` (watch, уведомления, доставка
между сессиями, диалог к человеку) и почти не тронул первую: агент должен думать, что
сохранить, что выгрузить, что ужать, а проект должен хранить указатели на длинные
файлы. При этом код оброс слоями, которые ни к одной боли манифеста не относятся.

Цифры с машины автора на 2026-09-16, на них опираются решения ниже:

- сессий с собственными заметками 42 из 315;
- `longrun log` не вызван ни разу ни в одном журнале;
- собственные заметки по тегам: fact 66, decision 19, todo 14, ctx 11, dead 8, pin 5;
- общие заметки по тегам: fact 40, decision 21, dead 13, pin 13;
- watch: 46 записей, 39 сработали, 34 из них типа `at`, 8 `cmd`, 4 `pr-merged`;
- оркестратор поднимался один раз, доска создавалась один раз, ledger не заводился ни разу;
- в SESSIONS этого проекта 33 строки, живых две.

## Источники правды и правила

1. `research/MANIFESTO.ru.md` - замысел. Расходится с README или SKILL.md - прав манифест.
2. `research/BACKLOG.md` - открытые дефекты B1-B5 и решение D1 про позиционирование.
3. `skill/longrun/scripts/longrun` - поведение. Расходится с документацией - прав код,
   документацию чинить.
4. Тесты: `tests/run.sh` (202), `tests/scenarios.sh` (30), `tests/orchestrator.sh` (64),
   `tests/ask.sh` (30). Все четыре зеленые до и после каждого этапа. Файлы `tests/last-run*.txt`
   обновлять при каждом прогоне: сейчас они старше кода (последний прогон 14.09, скрипт
   менялся 15.09).
5. Один этап = одна ветка = один PR. Этапы независимы, если не сказано иное. Порядок
   ниже выбран под окно промо 15.09-05.10.2026: сначала то, что увидит новый пользователь.
6. Факты про сам Claude Code брать из документации code.claude.com/docs или из строк
   бинаря `~/.local/share/claude/versions/2.1.238`. Не из README этого проекта.
7. Заметки на диске (longrun add) по-английски, как велит SKILL.md. Этот файл и общение
   с пользователем по-русски. Типографика: кавычки простые, тире только обычный минус,
   без буквы "ё", стрелки `->`.
8. Переводы README (ru, zh-CN, ja, ko) и курс трогать только на этапе 10, по канону
   `docs/TRANSLATION.md`.
9. Точки решения помечены `РЕШЕНИЕ:`. Там остановиться и спросить пользователя, не
   выбирать самому.

## Что проверено, что нет

Проверено (код, тесты, документация Claude Code, бинарь):

- stdout PreCompact-хука становится блоком "Additional Instructions" промпта
  суммаризатора, для автокомпакции тоже (бинарь: `newCustomInstructions -> customInstructions`).
- SendMessage и ListAgents между локальными сессиями встроены в Claude Code с 2.1.224,
  страница `cross-session-messaging` в документации. longrun шлет в тот же сокет.
- `/goal`: одна сессия, оценщик судит по разговору после каждого хода, через сессии
  счетчики не переносятся. Субагенты не получают SessionStart-хуки.
- Автопамять: каталог на проект, первые 200 строк или 25 КБ MEMORY.md грузятся каждый разговор.
- Встроенные /loop и CronCreate работают только пока сессия запущена и простаивает,
  пропуски не догоняют, истекают через 7 дней.

Не проверено, не опираться без проверки:

- лимит вывода хука 10000 символов, на котором держится `inject_max_bytes`: в документации
  нет, в строках бинаря не нашелся;
- что launchd догоняет пропущенные тики после сна;
- срабатывание PermissionRequest и Notification хуков в приложении;
- сколько проверок из 202 завязано на удаляемые в этапах 8-9 слои.

## Этап 2. Дайджест и дельта: дефекты

Боль манифеста: "заметки ведутся и помнятся", а сейчас самые новые теряются.

### 2.1 B1: дайджест режет самые новые заметки

Где: `build_digest` (строки ~5196-5297). Блокам заметок дается `cap + 400` байт
(~5222, ~5226), итог обрезается по хвосту (~5296). Заметки рендерятся от старых к новым,
хвост - это новые собственные заметки, потом новые общие.

Что сделать:

- Если после сброса необязательных блоков все еще больше `inject_max_bytes`, выкидывать
  из блоков заметок записи, начиная с самых старых не-`pin`, по одной, до влезания.
  Показать строку `(N older entries omitted: longrun notes)`.
- В `cmd_config` / `config_coerce`: `notes_max_bytes + session_notes_max_bytes + 600`
  не больше `inject_max_bytes`, иначе отказ с объяснением. Проверять и при `config set`
  любого из трех ключей.
- `notes_warn_pct` и `notes_autoprune_pct` считать от того, что реально влезает в дайджест,
  а не от `notes_max_bytes`.

Тест: в `tests/run.sh` раздел "digest size cap" - добавить проверку, что при переполнении
в дайджесте есть самая новая запись и нет самой старой не-pin.

### 2.2 Обрезанная дельта помечается увиденной целиком

Где: `shared_delta` (~5019-5042). `m["shared_seen"] = cur` выставляется на строке ~5027
до обрезки по `shared_delta_max_bytes` на ~5040. Записи за пределами бюджета сессия
не увидит никогда.

Что сделать: помечать увиденными только те id, что вошли в вывод; остальные покажутся
на следующем ходу.

Тест: сценарий S3 - добавить случай с тремя длинными записями и бюджетом на одну.

### 2.3 Напоминание можно пропустить на целое окно

Где: `PostToolUseFailure` увеличивает `tools_since_note` (~5999) без напоминания,
`PostToolUse` напоминает только при `tools_since_note % nudge_tools == 0` (~5983).

Что сделать: заменить равенство на "перешагнули порог с прошлого напоминания":
хранить `nudged_at_tools`, напоминать когда `tools_since_note - nudged_at_tools >= nudge_tools`.
То же для ходов. Этап 3 перепишет само напоминание, но порог нужен и там.

### 2.4 Мелочи

- `deliver_inbox` (~3113) режет тело сообщения до 4000 символов молча. Дописать
  `... (truncated, full text: inbox/.archive/<file>)`.
- `halt_exempt` (~2852): `bash -c "longrun resume"` не пропускается. Проверять не только
  первое слово, а любое вхождение `longrun resume` в команде. Это не граница безопасности,
  только удобство.
